# Weblog 部署与维护手册（小白版）

> 本手册面向**没有太多服务器经验的用户**，从零开始一步步教你把这套博客系统部署到自己的服务器上，以及日常如何维护（更新、备份、排错）。
>
> 看完本手册，你不需要懂 Docker、Java、MySQL 的原理，只需要照着命令复制粘贴即可。

## 一、这套系统是什么

Weblog 是一套前后端分离的博客系统，跑起来后由 **4 个容器**协同工作：

| 容器 | 作用 | 通俗理解 |
|------|------|---------|
| `weblog-mysql` | 数据库 | 存文章、评论、用户等所有数据 |
| `weblog-minio` | 对象存储 | 存图片、封面等文件（类似"网盘"） |
| `weblog-backend` | 后端服务 | 处理业务逻辑、接口 |
| `weblog-frontend` | 前端 + 网关 | 你浏览器看到的网页，并转发请求 |

> **容器**可以简单理解成"轻量的虚拟机"，每个容器独立运行一个程序，通过 `docker compose` 一条命令统一管理。

**技术栈**：Spring Boot 2.7（后端）+ Vue 3（前端）+ MySQL 8（数据库）+ Minio（文件存储）+ Nginx（网关）。

## 二、部署前需要准备什么

| 准备项 | 说明 |
|--------|------|
| 一台服务器 | 推荐 2核4G 以上，Linux 系统（推荐 Ubuntu 22.04/24.04） |
| 能连上服务器的终端 | Windows 用 PowerShell/CMD，Mac 用终端 |
| 一个 GitHub 账号（可选） | 拉取代码用 |
| 域名 + SSL 证书（可选） | 想用 https 访问时才需要 |

> **服务器推荐**：腾讯云轻量应用服务器（Lighthouse）、阿里云 ECS 均可，2核4G 大约几十元/月，新用户常有优惠。

## 三、第一步：购买并登录服务器

### 3.1 购买（以腾讯云为例）
1. 打开腾讯云官网，进入「轻量应用服务器」购买页。
2. 地域选离你近的（如北京、上海、广州）。
3. 镜像/系统选 **Ubuntu 22.04 或 24.04**（纯系统即可，不用选应用镜像）。
4. 套餐选 **2核4G** 起步。
5. 设置实例密码（**务必记住**，后面登录要用）。

### 3.2 登录服务器
购买完成后，在控制台找到你的服务器公网 IP（形如 `123.45.67.89`），然后在你本地终端输入：

```bash
ssh root@你的服务器IP
```

首次连接会提示确认，输入 `yes`，然后输入你设置的密码即可。

> 登录成功后，终端提示符会变成 `root@xxx:~#`，说明你已经进入服务器了。后面所有命令都在这里执行。

## 四、第二步：安装 Docker

Docker 是运行容器的基础环境，只需安装一次。

```bash
# 一条命令安装 Docker 和 Docker Compose
apt-get update -y
apt-get install -y docker.io docker-compose-v2

# 启动 Docker 并设置开机自启
systemctl enable docker
systemctl start docker
```

验证安装成功（看到版本号即成功）：

```bash
docker -v
docker compose version
```

### 4.1（重要）配置国内镜像加速

因为服务器在国内，直接拉取国外镜像会很慢甚至失败，需要配置加速器：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io"
  ]
}
EOF
systemctl restart docker
```

把项目代码下载到服务器上：

```bash
# 进入 /opt 目录
cd /opt

# 拉取代码（把下面的地址换成你的代码仓库地址）

cd /opt/weblog
```

## 六、第四步：配置环境变量

项目用 `.env` 文件保存敏感配置（密码、密钥等）。我们复制模板后修改：

```bash
cd /opt/weblog/deploy

# 复制模板为 .env
cp .env.example .env
```

然后编辑 `.env`，**至少修改两处密码**：

```bash
nano .env
```

重点改这两行（把值换成你自己的强密码/密钥）：

```bash
# MySQL root 密码（改成你自己的，别用 root）
MYSQL_ROOT_PASSWORD=改成你自己的强密码

# Minio 账号密码（改掉）
MINIO_ROOT_USER=改成你的用户名
MINIO_ROOT_PASSWORD=改成你的强密码

# JWT 密钥（用下面的命令生成一个随机的）
WEBLOG_JWT_SECRET=改成随机长字符串
```

生成随机 JWT 密钥的命令：

```bash
openssl rand -base64 48
```

把输出的一长串字符填到 `WEBLOG_JWT_SECRET` 后面。

> `nano` 编辑器用法：改完后按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。不会用 nano 的话，也可以用 `vi`。

**一个关键的坑**：如果服务器上 docker 组的 GID 不是默认值，需要确认 `.env` 里的 `DOCKER_GID`：

```bash
getent group docker
```

输出形如 `docker:x:112:`，中间的 `112` 就是 GID。把 `.env` 里的 `DOCKER_GID=999` 改成这个值（本手册默认服务器是 112）。

## 七、第五步：一键启动

```bash
cd /opt/weblog/deploy

# 启动整套服务（首次会自动构建镜像，需要几分钟）
docker compose up -d --build
```

> `-d` 表示后台运行；`--build` 表示先构建镜像。首次运行会自动下载 MySQL、Minio 等镜像，需要等几分钟到十几分钟（取决于网速）。

### 7.1（可能遇到）Minio 镜像拉取失败

`minio/minio` 官方镜像在 Docker Hub 已下架，国内加速源可能拉不到。如果启动时看到 `403 Forbidden` 或 `not found` 报错，用下面的方法手动拉取：

```bash
# 从华为云同步站拉取 minio 镜像
docker pull swr.cn-north-4.myhuaweicloud.com/ddn-k8s/quay.io/minio/minio:RELEASE.2024-04-18T19-09-19Z
docker pull swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/minio/mc:latest

# 重命名成本地可识别的名字
docker tag swr.cn-north-4.myhuaweicloud.com/ddn-k8s/quay.io/minio/minio:RELEASE.2024-04-18T19-09-19Z minio/minio:latest
docker tag swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/minio/mc:latest minio/mc:latest

# 重新启动
docker compose up -d
```

### 7.2（可能遇到）后端启动失败 / 日志权限报错

如果后端容器一直重启，日志里出现 `logs/weblog.log (Permission denied)`，是因为日志目录权限不对，执行：

```bash
chown -R 999:999 /opt/weblog/deploy/logs
docker compose up -d
```

打开浏览器，访问：

```
http://你的服务器IP/
```

- 管理后台地址：`http://你的服务器IP/login`
- 管理员账号：`admin` / `123456`（**首次登录后请立即修改密码**）

## 九、日常维护

### 9.1 查看日志

```bash
# 查看后端日志（实时）
docker logs -f weblog-backend

# 查看前端（Nginx）日志
docker logs -f weblog-frontend

# 查看最近 100 行后端日志
docker logs --tail 100 weblog-backend
```

### 9.2 重启服务

```bash
# 重启所有服务
cd /opt/weblog/deploy && docker compose restart

# 只重启后端
docker compose restart backend
```

### 9.3 停止 / 启动服务

```bash
# 停止所有服务（不删数据）
docker compose stop

# 再次启动
docker compose start
```

### 9.4 更新代码并重新部署

当你修改了代码并推送到 Git 仓库后，在服务器上更新：

```bash
cd /opt/weblog

# 拉取最新代码
git pull

# 重新构建并重启（会自动更新变化的服务）
cd deploy && docker compose up -d --build
```

### 9.5 数据备份（重要！）

项目提供了备份脚本，会备份数据库 + 上传文件到 `backups/` 目录：

```bash
cd /opt/weblog/deploy/scripts
bash backup.sh
```

**建议配置定时备份**（每天凌晨自动备份），用 cron：

```bash
# 编辑定时任务
crontab -e

# 添加下面这行（每天凌晨 3 点备份）
0 3 * * * cd /opt/weblog/deploy/scripts && bash backup.sh
```

### 9.6 查看资源占用

```bash
# 查看各容器占用的内存
docker stats --no-stream
```

## 十、常见问题排查（FAQ）

### Q1：访问网站显示"无法访问"或超时
**原因**：服务器防火墙/安全组没开放 80 端口。
**解决**：在腾讯云/阿里云控制台 → 防火墙/安全组，添加规则放行 **TCP 80** 端口（和 9001，如果要用 Minio 控制台）。

### Q2：登录时滑块验证码图片不显示
**原因**：反向代理没把 `/api` 前缀正确转发。
**解决**：检查 `deploy/nginx.conf` 中 `/api/` 是否配置了 `uri strip_prefix /api`（本项目已配置好，正常不需要改）。

### Q3：后端容器一直重启（Restarting）
**解决**：先看日志定位原因：
```bash
docker logs weblog-backend
```
- 看到 `Permission denied`（日志权限）→ 执行 `chown -R 999:999 /opt/weblog/deploy/logs`
- 看到 `Connection refused`（连不上数据库）→ 等 MySQL 完全启动后再重启：`docker compose restart backend`

### Q4：数据库数据会丢吗？
**不会**。MySQL、Minio 的数据都存在 Docker 的持久化卷（volume）里，即使删除容器、重启服务器，数据都还在。除非你手动执行 `docker compose down -v`（这个命令会删数据，慎用）。

### Q5：怎么查看 Minio 管理后台？
访问 `http://你的服务器IP:9001`，用 `.env` 里设置的 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` 登录。

### Q6：内存不够 / 服务器卡
2核4G 跑这套系统 + Jenkins 会比较吃紧。如果只跑博客（不跑 Jenkins），内存是够的。如果卡，可以在 `docker-compose.yml` 里调低各服务的 `mem_limit`。

### Q7：如何彻底卸载 / 重新部署？
```bash
cd /opt/weblog/deploy
docker compose down          # 停止并删除容器（保留数据）
docker compose down -v       # 连同数据一起删除（慎用！）
```

## 十一、进阶：HTTPS 与域名

默认用 `http://IP` 访问。想要更专业的 `https://你的域名`，需要：

### 11.1 绑定域名
1. 买一个域名，在域名服务商处添加 A 记录，指向你的服务器 IP。
2. 在腾讯云/阿里云完成域名备案（中国大陆服务器必须备案）。

### 11.2 配置 HTTPS
项目已提供 SSL 配置模板 `deploy/nginx.ssl.conf.example`。简要步骤：

1. 申请 SSL 证书（免费可用 Let's Encrypt，或云厂商的免费证书）。
2. 把证书文件放到服务器。
3. 参考 `deploy/nginx.ssl.conf.example` 修改 `deploy/nginx.conf`，加上 443 监听和证书路径。
4. 重新构建前端镜像：
   ```bash
   cd /opt/weblog/deploy && docker compose up -d --build frontend
   ```

> HTTPS 配置涉及域名和证书，属于进阶操作。如果暂时用 IP 访问，可以跳过本节，不影响使用。
