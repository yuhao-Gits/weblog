# Weblog 设计文档

## 1. 系统架构

### 1.1 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                        浏览器                            │
│              Vue 3 SPA（前台 + 管理后台）                  │
└───────────────┬─────────────────────────┬───────────────┘
                │ HTTP/HTTPS              │ WebSocket
                │ (Axios + JWT)           │ (/chat/ws)
                ▼                         ▼
┌─────────────────────────────────────────────────────────┐
│                    Nginx（反向代理/静态资源）              │
└───────────────────────────────┬─────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────┐
│              Spring Boot 应用（weblog-server）            │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  │ Security │ │ 业务模块  │ │ WebSocket│ │ 定时任务  │   │
│  │ + JWT    │ │ (Module) │ │ Handler  │ │  (Task)  │   │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘   │
└───────┬─────────────────┬─────────────────┬─────────────┘
        │ MyBatis-Plus    │ Lucene 索引      │ 本地文件
        ▼                 ▼                  ▼
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│   MySQL 8    │   │ lucene-index  │   │  ./uploads   │
└──────────────┘   └──────────────┘   └──────────────┘
```

### 1.2 分层架构（后端）

```
controller → service → mapper → MySQL
                │
                ├─→ LuceneHelper（站内搜索索引）
                ├─→ 事件发布（Spring Event 异步同步索引/阅读量）
                └─→ 邮件通知（评论通知）
```

## 2. 技术选型

| 类别 | 选型 | 说明 |
|------|------|------|
| 后端框架 | Spring Boot 2.7.18 | 稳定成熟，生态完善 |

| UI 组件 | Element Plus + Tailwind CSS | 后台组件 + 前台原子化 |
| 状态管理 | Pinia | 用户/博客设置 |
| 图表 | ECharts 5 | 仪表盘可视化 |
| 编辑器 | md-editor-v3 | Markdown 编辑 |

## 3. 数据库设计

### 3.1 ER 关系

```
t_user ──┐
t_category ──┐
t_tag ──(t_article_tag_rel)──┐
                             ├── t_article ── t_comment
t_blog_settings              │
t_statistics                 │
t_knowledge_directory ── t_knowledge_article
t_chat_message
```

### 3.2 表结构清单

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| t_user | 用户 | username(uk), password(BCrypt), role |
| t_category | 分类 | name |
| t_tag | 标签 | name |
| t_article | 文章 | title, content(md), content_html, category_id, is_top, status |
| t_article_tag_rel | 文章-标签关联 | article_id, tag_id |
| t_blog_settings | 博客设置 | blog_name, avatar, 敏感词, 评论审核开关, 邮箱配置 |
| t_statistics | 访问统计 | date(pk), pv, uv, article_count |
| t_comment | 评论 | article_id, parent_id(树形), nickname, qq, content, status(审核) |
| t_knowledge_directory | 知识库目录 | title, parent_id(二级树), sort |
| t_knowledge_article | 知识库文章 | title, content, directory_id, is_top, status |
| t_chat_message | 聊天消息 | nickname, avatar, content, type |

> 完整 DDL 见 `weblog-server/src/main/resources/schema.sql`

### 3.3 主键策略
- 全局采用 **雪花算法（Snowflake）** 生成 64 位 Long 主键（MyBatis-Plus `assign_id`）
- 因 JavaScript Number 精度仅安全到 2^53，后端通过 Jackson `ToStringSerializer` 将 Long 全局序列化为 **String**，前端原样透传，避免精度丢失

## 4. 关键设计

### 4.1 统一响应结构

```json
{
  "code": "10000",   // 成功；其余为业务错误码
  "message": "成功",
  "data": {}
}
```

- `Result<T>` 统一封装，`PageResult<T>` 承载分页数据
- `ResponseCodeEnum` 定义错误码（登录失败 20002 等）
- `GlobalExceptionHandler` + `BizException` 统一异常处理

### 4.2 鉴权流程

```
登录 → 滑块验证码校验 → 密码认证(AuthenticationManager)
     → 颁发 JWT(含 username/role) → 前端存储 Token
请求 → JwtAuthenticationFilter 解析 Token → 设置 SecurityContext
     → @PreAuthorize("hasRole('ADMIN')") 控制写接口
```

- 静态资源 `/files/**`、公开路由 `/knowledge/**`、`/chat/**`、`/captcha/**` 在 SecurityConfig 放行
- 游客 `ROLE_GUEST` 仅可查询，写接口返回 403

### 4.3 站内搜索（Lucene）

```
启动 → LuceneIndexRunner 全量建索引
文章增删改 → Spring Event(ArticleIndexEvent) → Listener 异步同步索引
检索 → LuceneHelper 分词查询 + 高亮
```

- 使用 `SmartChineseAnalyzer` 中文分词，无需额外 IK 词典
- 索引存储在 `lucene-index/` 目录

### 4.4 聊天室（WebSocket）

- 端点 `/chat/ws`，`ChatWebSocketHandler` 处理连接/消息/断开
- 消息协议 JSON：`{type: join|message|ping}`
- `ConcurrentHashMap<String, WebSocketSession>` 维护在线会话
- 历史消息采用 **游标分页**（`lastMessageId + size`），雪花 ID 降序取再反转升序

### 4.5 滑块验证码

- 纯 Java AWT 自实现（避免 tianai-captcha 离线依赖风险）
- 生成 320×160 渐变背景 + 圆角缺口 + 拼图，缺口 x ∈ [48, 272]
- 校验容差 6px，失败保留 token 允许重试
- **二次校验**：滑块校验通过后颁发一次性 passToken，登录时消费（防重放，5 分钟超时）

### 4.6 异步处理
- 项目未启用 `@EnableAsync`，使用 `@Resource(name="asyncTaskExecutor")` 手动提交线程池
- 场景：文章阅读量 +1、Lucene 索引同步、邮件通知

### 4.7 定时任务
- `PvStatisticsTask`（`@Scheduled`）每日统计 PV 访问量

## 5. 前端设计

### 5.1 目录结构
```
src/
├── api/          # 接口封装（front/admin/comment/chat/knowledge/captcha）
├── stores/       # Pinia（user、博客设置）
├── composables/  # useBlogSettings、useTheme
├── router/       # 路由（前台 + 后台，登录守卫）
├── layout/       # FrontLayout / AdminLayout
├── views/        # front（前台页）+ admin（后台页）
└── components/   # front 组件 + SliderCaptcha
```

### 5.2 设计系统
- CSS 变量令牌：`--brand/--surface/--text-*/--border/--shadow-*`
- 品牌渐变：靛蓝 `#6366f1` → 紫 `#8b5cf6` → 粉紫 `#d946ef`
- 字体：Inter（正文）+ Playfair Display（衬线标题）+ JetBrains Mono（代码）
- `html.dark` class 切换明暗主题

### 5.3 路由与鉴权
- 前台路由挂载于 `FrontLayout`，后台路由挂载于 `AdminLayout`
- 全局路由守卫：访问 `/admin/**` 需 Token，未登录跳转登录页
